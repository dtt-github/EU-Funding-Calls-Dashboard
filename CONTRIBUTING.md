# Contributing to EU Funding Calls Dashboard

Thank you for your interest in contributing! This project is open source under the MIT License and we welcome improvements from the community.

## How to Contribute

### 1. Fork and Clone

```bash
git clone https://github.com/<your-username>/EU-Funding-Calls-Dashboard.git
cd EU-Funding-Calls-Dashboard
```

### 2. Create a Feature Branch

Always branch off `main`:

```bash
git checkout -b feature/your-feature-name
```

Use a descriptive branch name, e.g. `fix/search-ranking`, `feature/export-csv`, `docs/api-fields`.

### 3. Make Your Changes

- This is a **zero build-step** project — pure HTML, CSS, and vanilla JavaScript.
- Open `index.html` in a browser or use `python3 -m http.server 8000` to serve locally.
- Test your changes in both light and dark mode.
- Test on mobile viewport widths if you're touching layout or CSS.

### 4. Commit

Write clear, concise commit messages that explain *why* the change was made:

```
Fix search ranking for industry-term queries

Previously exact substring matches were returned without
relevance scoring, causing "capacity building" to rank
above actual construction-industry calls.
```

### 5. Push and Open a Pull Request

```bash
git push origin feature/your-feature-name
```

Then open a Pull Request against the `main` branch on GitHub. In your PR description:

- Summarise what changed and why
- Include screenshots if the change is visual
- Note any testing you performed

## Branch Protection

Direct pushes to `main` are restricted. All changes must go through a Pull Request and be reviewed before merging.

## Code Guidelines

### General

- **No build tools** — no Webpack, Vite, npm, etc. This project ships raw files to GitHub Pages.
- **No external frameworks** — keep it vanilla HTML/CSS/JS. Library additions (CDN only) should be discussed in an issue first.
- **Cache busting** — if you modify `css/styles.css`, `js/app.js`, `js/auth.js`, or `js/config.js`, bump the `?v=N` query parameter in `index.html`.

### JavaScript

- Use `var` or `let`/`const` consistently within a function — the codebase currently uses a mix but prefers `var` inside IIFEs.
- Avoid adding comments that just narrate what code does. Comment only non-obvious intent or trade-offs.
- Test search changes with a variety of queries: industry terms ("construction", "ai", "energy"), topic IDs ("CL5-2026-09"), and edge cases (empty input, single character).

### CSS

- Use existing CSS custom properties (`var(--accent)`, `var(--bg-surface)`, etc.) instead of hardcoded colours.
- Ensure changes work in both `[data-theme="light"]` and `[data-theme="dark"]`.
- Keep responsive breakpoints consistent with existing media queries.

### Data

- Do not manually edit `data/calls.json` — it is auto-generated by `scripts/fetch_calls.py`.
- If you change the fetch script, run it and verify the output before committing.

## What to Contribute

Here are some ideas:

- **Search synonyms** — expand the `SYNONYMS` dictionary in `app.js` for more industries and topics
- **Accessibility** — improve ARIA labels, keyboard navigation, screen reader support
- **Localisation** — translate the UI into other EU languages
- **Export formats** — add CSV or PDF export for selected calls
- **Data enrichment** — pull additional fields from the EU API (e.g. budget, funding rate)
- **Performance** — optimise rendering for large result sets
- **Bug fixes** — check the Issues tab for open bugs

## Reporting Issues

Open a [GitHub Issue](https://github.com/dtt-github/EU-Funding-Calls-Dashboard/issues) with:

- Steps to reproduce
- Expected vs actual behaviour
- Browser and OS version
- Screenshots if applicable

## Code of Conduct

Be respectful. We follow common open-source etiquette — be constructive, assume good intent, and keep discussions focused on the project.
